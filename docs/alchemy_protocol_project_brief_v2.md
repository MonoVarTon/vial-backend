Статус: концепция + черновая юнит-экономика. Последнее обновление: август 2026 (ревизия 2).
Курс на момент расчётов: 1 TON ≈ $1.40.

**Чейнджлог ревизии 2:** механика Vault/Recycle зафиксирована как **чистая рарность** —
протокол не несёт денежных обязательств по "джекпотам" (нет прямых TON-выплат за редкий исход).
Юзер всегда получает новый NFT; переменная — тир его редкости. Раздел 5 и финмодель (раздел 6)

## 1. Контекст и отправная точка

Владелец коллекции на OpenSea хочет перенести/возобновить коллекцию на TON (getgems) и параллельно ищет принципиально новый продукт на стыке AI + TON NFT, который можно построить поверх этой инфраструктуры.

Технический фундамент для миграции коллекции уже готов отдельно (см. раздел 7 — скрипт `getgems_nft_uploader`).

## 2. Рыночное исследование: почему что-то залетает на getgems

### 2.1 Категории успеха
- **Telegram Gifts (коллекционные подарки)** — главный источник объёма на getgems сейчас. Редкость определяется 4 осями: модель, фон, символ, номер. Flagman — Plush Pepe, floor ~5100 TON, топовые экземпляры — $90-120 тыс+. Рекордная продажа: Scared Cat с редким сочетанием фона/паттерна — 22 222 TON (~$27 400).
- **Арт-проекты с сильным community-запуском.** TON Punks: >700 тыс. TON на дропе, вторичка >750 тыс. TON, маркетинговый бюджет <$100 тыс. Rich Cats: распродан на пресейле. Эллен Шейдлин (первый веб2-художник на TON): $170 тыс. за один день на mystery-box механике.
- **Геймификация.** Lucky Buy (вероятностная покупка 1-75% за фикс. взнос, всё ончейн-прозрачно) и Gift Crafting (сжигание 1-4 подарков ради шанса на редкую версию, введено с обновления Telegram 12.4, 8 февраля 2026).

### 2.2 Ключевые триггеры (обобщённо)
1. Видимая глазами редкость (трейты, а не абстрактный процент)
2. Азарт/геймификация (вероятностные механики)
3. Дефицит на пресейле → FOMO
4. Нативная встроенность в Telegram (аудитория уже там)
5. Низкий газ → низкий порог входа
6. Алгоритм топа getgems: обновляется ~раз в час, важен объём торгов за период, не разовая крупная продажа
7. Личный бренд создателя как сигнал доверия

## 3. Ключевая техническая находка: почему кросс-коллекционного крафта не существует

Из официальной документации Telegram (`core.telegram.org/api/gifts`, метод `payments.craftStarGift`):

> Крафтить можно только 1-4 подарка **одного и того же `gift_id`** (то есть строго внутри одной коллекции).

Это **не ограничение блокчейна** — оба подарка технически идентичны как TEP-62/64 NFT-контракты на TON, смарт-контракты прекрасно совместимы. Ограничение — **продуктовое решение на уровне централизованного API Telegram**: каждый тип подарка имеет свой закрытый пул "crafted"-моделей (арт, нарисованный художниками именно под этот тип), и формула вероятностей (`craft_chance_permille`) жёстко завязана на предположение об одном типе.

**Вывод:** это ниша, которую Telegram физически не может закрыть без ручной отрисовки бесконечных комбинаций — и именно её решает AI-генерация на лету. Это ядро продуктовой идеи.

### 3.1 Как физически устроено "сжигание" на блокчейне
- Полное удаление данных с блокчейна невозможно (неизменяемость истории) — ни на TON, ни где-либо ещё
- Практический burn = soft-burn: контракт обнуляет `owner_address` и выставляет флаг `burned = true` (ровно так же устроен `starGiftUnique.burned` у самого Telegram)
- Технически контракт физически остаётся в блокчейне, просто становится нетрансферабельным
- Отдельный нюанс TON: контракты с нулевым балансом реально замораживаются и в перспективе удаляются сетью из-за storage rent — но это неуправляемый garbage collection, не дизайн-паттерн для burn-логики

## 4. Продуктовая концепция: Alchemy Protocol ("AI Alchemist")

Кросс-коллекционный синтез NFT: юзер сжигает 2-4 NFT (из любых коллекций на TON, не только одной), AI анализирует их и генерирует совершенно новый уникальный NFT, наследующий осмысленные элементы каждого сожжённого предмета.

### 4.1 Технический поток
1. Клиент (Telegram Mini App / сайт с TonConnect) — выбор 2-4 NFT из кошелька
2. Off-chain индексер (toncenter/tonapi) валидирует, что это реальные TEP-62 контракты (анти-фрод фильтр против фейковых "пустышек")
3. Юзер подписывает одну транзакцию — трансфер выбранных NFT на адрес контракта Alchemy
4. Контракт Alchemy soft-burns полученные предметы, эмитит событие
5. Off-chain воркер подхватывает событие, тянет метаданные сожжённых NFT
6. AI-пайплайн: анализ изображений (CLIP-эмбеддинги, цвета, стиль) → промпт → генерация
7. Результат заливается на IPFS (двойной pinning — Pinata + nft.storage, без единой точки отказа)
8. Контракт минтит новый NFT на кошелёк юзера через `mint_synthesized`
9. getgems подхватывает автоматически при следующей индексации — **партнёрство с getgems не требуется**, площадка индексирует любую валидную TEP-62/64 коллекцию; верификация нужна только для топ-выдачи, не для факта появления

### 4.2 Верифицируемость и качество
- Seed для генерации выводится детерминированно из хэшей сожжённых NFT — результат воспроизводим и проверяем не как случайный рандом бэкенда
- В метаданные добавляется трейт `Lineage` — ссылки на адреса сожжённых родительских NFT (нарративная и рыночная ценность происхождения)
- Формат изображения — по спецификации getgems: квадрат 400-1000px, png/jpg/webp/svg, до 30MB

### 4.3 Масштабирование
- Бутылочное горлышко — не блокчейн (TON быстрый и дешёвый), а AI-генерация
- Архитектура разделяет ончейн-подтверждение burn и офчейн-генерацию через очередь задач (job queue), юзер получает уведомление в боте когда готово (~30-90 сек)
- Пиковые нагрузки — через serverless GPU с автоскейлингом (Replicate/Fal.ai), не собственные GPU
- Обязательная модерация контента перед минтом (NSFW-фильтр, проверка на копирование чужого IP) — постфактум откатить нельзя, только предмодерация

## 5. Токеномика: двухтировая модель (Recycle + Vault)

**Ключевое решение (ревизия 2): чистая рарность, без денежных обязательств протокола.**
Юзер получает новый NFT при каждой попытке — это гарантированный результат, не лутбокс с шансом остаться ни с чем. Единственная переменная — тир редкости итогового NFT (трейты, визуальная ценность, позиция в коллекции). Протокол никогда не выплачивает TON напрямую за случайный исход. Это принципиально: прямая денежная выплата за вероятностный исход — юридически лотерея/гэмблинг почти в любой юрисдикции (см. открытый вопрос №4); рарность NFT без денежной выплаты — та же ниша, где уже безопасно работает сам Telegram (Gift Crafting).

Изначальная проблема, которую решает формула ниже: если убрать зависимость шансов от ценности сожжённого — юзеры сжигали бы самый дешёвый мусор ради шанса на топовый по редкости результат, обесценивая сам тир Vault.

### 5.1 Формула шансов и таблицы вероятностей

Шанс на высокий тир редкости считается по аналогии с `craft_chance_permille` у Telegram — как сумма оценок ценности (floor price коллекции + редкость атрибутов) всех сожжённых предметов. Мусор даёт мусорные шансы **по конструкции формулы**, не административным запретом. Итоговое распределение по тирам (индустриальные бенчмарки gacha-механик, требуют калибровки по реальным данным getgems):

**Recycle (мусорный вход, floor не ограничен снизу)**

| Тир | Вероятность |
|---|---|
| Common | 70% |
| Uncommon | 20% |
| Rare | 8% |
| Epic | 1.8% |
| Legendary | 0.19% |
| Mythic | 0.01% |

**Vault (вход от 5-10 TON floor — заведомо ценное сырьё)**

| Тир | Вероятность |
|---|---|
| Common | 20% |
| Uncommon | 30% |
| Rare | 30% |
| Epic | 15% |
| Legendary | 4.5% |
| Mythic | 0.5% |

### 5.2 Два раздельных продукта на общей инфраструктуре

**Recycle (шредер, casual)**
- Принимает что угодно, без порога входа
- Фиксированный сбор: 0.5 TON ($0.70) за попытку
- Дешёвая/быстрая AI-модель
- Себестоимость: газ ~0.08 TON + AI ~0.015 TON ≈ 0.095 TON
- Чистая маржа: ~81%

**Vault (VIP, событийный)**
- Порог входа: суммарная floor-ценность сжигаемого от ~5-10 TON
- Более высокий сбор: 5 TON ($7.00) за попытку
- Премиальная AI-модель, эффектная публичная подача (обратный отсчёт, лайв в Telegram-канале — по аналогии с mystery-box механикой Эллен Шейдлин)
- Себестоимость: газ ~0.1 TON + AI ~0.05 TON ≈ 0.15 TON
- Чистая маржа: **~97%** (нет расходной статьи на выплаты — платить нечем и незачем)

### 5.3 Экономическая связка между тирами
Recycle — объёмный низкомаржинальный поток, который держит вовлечённость и приучает аудиторию к продукту; Vault — событийный, высокомаржинальный, где громкие Legendary/Mythic результаты работают как маркетинг (публичная подача, ажиотаж), привлекающий новых людей в Recycle. Никакого treasury-пула под джекпоты не требуется — вся маржа обоих тиров идёт напрямую в накопление, без риска "разорения резерва" (проверено стресс-тестом в рамках проработки; при денежных выплатах риск был реальным — см. историю ревизии в рабочих материалах).

### 5.4 Анти-фарм защита
- Минимальный возраст NFT на блокчейне перед использованием в синтезе (7-14 дней) — против "начеканил-сжёг" в одну сессию
- Rate limiting по кошельку
- Требование торговой истории у коллекции сжигаемого NFT (защита от самодельного фейкового floor price)

### 5.5 Два источника дохода
| Источник | Когда приходит | Что покрывает |
|---|---|---|
| Фиксированный сбор за попытку | Сразу, каждый запуск | Газ + AI-инференс + чистая маржа (~81% Recycle / ~97% Vault) |
| Роялти с перепродаж результата на getgems (стандартные 5%) | Долгосрочно, по факту успеха на вторичке | Реальную долгосрочную прибыль, растущую вместе с рынком редких исходов |

## 7. Готовый технический актив: скрипт миграции коллекции на getgems

> **СТАТУС: НЕАКТИВНО.** Текущий фокус проработки — Alchemy Protocol целиком (разделы 3-6, 8). Миграция коллекции — фоновая ветка, отложена до отдельного решения вернуться к ней.

Файл: `getgems_nft_uploader/` (передан отдельным архивом ранее в этом чате).

Состав:
- `mint_collection.py` — подготовка метаданных, заливка на IPFS через Pinata, деплой коллекции и минт через библиотеку `tonutils` (официальный Python SDK для TON, поддерживает `CollectionStandard`/`CollectionEditable`, batch mint)
- `nft_data/template.json` — шаблон метаданных коллекции и NFT (формат TEP-64, совместимый с getgems)
- `.env.example` — плейсхолдеры для `PINATA_JWT` и `TON_MNEMONIC` (никогда не хардкодятся в коде)
- Режимы: dry-run по умолчанию (ничего не тратит) → `--mint` (тестнет) → `--mint --mainnet` (реальный минт)

Референсы:
- Спецификация метаданных getgems: `github.com/getgems-io/nft-contracts/blob/main/docs/metadata.md`
- Референсная реализация NFT-контрактов TON (TEP-62): `docs.ton.org/contracts/standard/tokens/nft/nft-reference`
- Библиотека tonutils: `tonutils.ness.su`
